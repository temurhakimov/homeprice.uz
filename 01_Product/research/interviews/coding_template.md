# Шаблон кодирования наблюдений: интервью HomePrice.uz

Версия 0.1 · 18.10.2026 · задача E6 · парный файл: `guide.md` (цель, отбор, гайд, правило инсайта)
Теги: [факт] / [гипотеза] / [проверить]. Респонденты только под кодами R1–R10 (резерв R11–R12). **Имён, телефонов, названий банков и компаний в файле нет и быть не должно.**

---

## 1. Как пользоваться

1. После каждого интервью (в течение 24 часов): заполнить **паспорт** (раздел 2) и **таблицу наблюдений** (раздел 3). Цитаты дословно, на языке оригинала, перевод рядом.
2. Присвоить **коды** из кодбука (раздел 4). Нет подходящего кода: записать наблюдение с кодом `NEW:` и описанием, кодбук обновится в разделе 9.
3. Прислать заметки мне (формат — раздел 10). Я закодирую, заполню **матрицу** (раздел 5), **таблицу покрытия** (раздел 6) и **реестр выводов** (раздел 7) по правилу гайда, раздел 8: не менее 3 независимых респондентов, иначе «анекдот».
4. Наблюдение ≠ интерпретация. В колонку «Наблюдение» идёт то, что человек сказал или сделал. Мои и ваши предположения — в колонку «Комментарий интервьюера».

**Типы наблюдений (колонка «Тип»):**

| Тип | Значение | В порог 3 |
|---|---|---|
| Ф | Факт из собственного опыта респондента («в последний раз я…») | да |
| Н | Наблюдение интервьюера за поведением (блок S: что сделал на сайте) | да |
| Ч | Пересказ чужого опыта («знакомым банк назначил…») | нет |
| М | Мнение, оценка, ожидание без примера из прошлого | нет (если есть пример из прошлого, кодируется как Ф) |
| Г | Гипотетика («я бы заплатил…», ориентир «слишком дорого/дёшево», E9) | нет |

**Источник реплики (колонка «П/В»):** **П** — респондент сказал сам до того, как вы задали вопрос на эту тему; **В** — в ответ на ваш вопрос.

## 3. Таблица наблюдений (по одному разделу на респондента)

Столбцы: **ID** `R3-07` (код респондента и порядковый номер) · **Блок** (0–5, A–E, GOV, S) · **Тип** (Ф/Н/Ч/М/Г) · **П/В** · **Цитата дословно (язык оригинала)** · **Перевод** (если нужен) · **Наблюдение** (что сказал или сделал, без оценок) · **Коды** · **Сила** (0–2) · **Гипотеза** (H1–H10) · **Комментарий интервьюера**

**Сила:** 0 — упомянуто вскользь; 1 — рассказано подробно; 2 — эмоциональный язык, потеря денег или времени, обходные пути, действие.

|---|---|---|---|---|---|---|---|---|---|---|
| R_-01 | | | | «[дословно, язык оригинала, без правок]» | | | | | | |
| R_-02 | | | | | | | | | | |
| R_-03 | | | | | | | | | | |

Правила записи:
- Цитата дословно; ничего не придумывать и не править. Если дословно не записали, оставить поле пустым, а в «Наблюдение» написать «по памяти».
- В цитате вместо имён и узнаваемых деталей: `[имя]`, `[банк]`, `[агентство]`.
- Одна мысль — одна строка.
- Термины респондента (как он называет оценку, цену, банк, калькулятор) записываются дословно и кодируются LANG.
- Ожидания и мнения, не связанные с прошлым опытом, записывать типом М; гипотетику — типом Г.

## 4. Кодбук

Принцип: щедро кодировать, потом объединять. Один фрагмент может иметь несколько кодов. Коды **SURP** (неожиданное) и **NEW** присваивать всегда, когда что-то не ложится в схему.

### 4.1 Триггер и ситуация (TRG)

| Код | Определение |
|---|---|
| TRG-BANK | Банк или ипотека потребовали оценку |
| TRG-SALE | Решение продавать квартиру |
| TRG-BUY | Решение покупать |
| TRG-GOV | Уведомление государства о массовой оценке, налог |
| TRG-OTH | Другой повод (запишите какой) |

### 4.2 Работа (JOB), из документа 06

| Код | Определение |
|---|---|
| JOB-ACCEPT | Нужна оценка, которую примет банк, нотариус, налоговая или суд |
| JOB-PRICE | Узнать реальную цену сделки |
| JOB-NEGOT | Убедить другую сторону объективной цифрой |
| JOB-RISK | Снизить риск (банк: завышенная цена; продавец: продешевить) |
| JOB-CLIENTS | Получить клиентов (оценщик, риелтор) |
| JOB-EMO | Эмоциональная: спокойствие, уверенность, избежать сюрпризов |
| JOB-SOC | Социальная: выглядеть подготовленным перед продавцом, банком, клиентом |

### 4.3 Боли (PAIN)

| Код | Определение |
|---|---|
| PAIN-TIME | Долгий срок или задержка |
| PAIN-COST | Высокая или неожиданная стоимость |
| PAIN-UNCERT | Неопределённость итоговой суммы (кредита, цены, оценки) |
| PAIN-IMPOSED | Оценщик или условия навязаны |
| PAIN-LOW | Оценка ниже цены сделки или ожидания |
| PAIN-OVERPRICE | Завышенные цены в объявлениях |
| PAIN-INFO | Нет данных о ценах сделок и аналогах |
| PAIN-TRUST | Недоверие к цифре, источнику или оценщику |
| PAIN-PROC | Бюрократия, документы |
| PAIN-IDLE | Простой, нехватка клиентов |

### 4.4 Решение и критерии (DEC)

| Код | Определение |
|---|---|
| DEC-WHO | Кто выбирает или решает (банк, брокер, сам клиент, знакомый) |
| DEC-CRIT | Критерий выбора (аккредитация в банке, срок, цена, отзывы, рекомендация) |
| DEC-INFL | Кто или что повлияло на выбор |

### 4.5 Альтернативы (ALT)

| Код | Определение |
|---|---|
| ALT-APPR | Оценочная компания или частный оценщик |
| ALT-BROKER | Брокер или риелтор |
| ALT-ADS | Объявления и сравнение цен |

### 4.6 Затраты и цена (COST)

| Код | Определение |
|---|---|
| COST-PAID | Факт: сколько заплатил (сумма, за что) |
| COST-TIME | Факт: сколько времени заняло |
| COST-SURPR | Неожиданные расходы или задержки |
| COST-FREE | Платить не хотел или ждал бесплатного результата |
| PRICE-RANGE | Ориентир «слишком дорого / слишком дёшево» (тип Г) |

### 4.7 Доверие и бумага (TRUST)

| Код | Определение |
|---|---|
| TRUST-DOC | Нужна бумага, подпись, принятие банком |
| TRUST-ONLINE | Отношение к онлайн-цифре |
| TRUST-SRC | Кому и чему верит (источники) |

### 4.8 Партнёры и B2B (B2B)

| Код | Определение |
|---|---|
| B2B-TOOL | Чем пользуются сейчас для цены или оценки |
| B2B-SPEND | Сколько платят за инструменты |

| B2B-FEAR | Опасения (конкуренция с KMT, потеря клиента, нейтральность) |

### 4.9 Государственная массовая оценка (GOV)

| Код | Определение |
|---|---|
| GOV-AWARE | Что знает или слышал |
| GOV-TAX | Налоговые опасения |
| GOV-FAIR | Справедливость, разные суммы у похожих квартир |
| GOV-ERR | Ошибки в данных |
| GOV-ACTION | Что сделал или решил (нажал кнопку, ничего, искал оценщика) |
| GOV-QUEST | Вопросы, на которые не нашёл ответа |

Отдельно от кодов оценки при ипотеке и продаже; тема сильно подсказана СМИ, поэтому Ф важнее М.

### 4.10 Показ сайта (SITE)

| Код | Определение |
|---|---|
| SITE-EXPECT | Ожидание до показа |
| SITE-FIRST | Что сделал первым (Н) |
| SITE-CONFUSE | Непонимание, затруднение (Н) |
| SITE-TRUST | Чему верит или не верит в результате |
| SITE-NEXT | Что сделал бы дальше |

### 4.11 Прочее

| Код | Определение |
|---|---|
| LANG | Слова и выражения респондента (как называет оценку, цену, банк, процесс): записывать дословно |
| SURP | Неожиданное, не вписывающееся в гипотезы |
| CONTRA | Противоречит ранее записанной гипотезе |
| NEW | Новый код: название и определение в комментарии |

## 7. Реестр выводов

Заполняется мной после получения заметок, затем вы подтверждаете или оспариваете.

| ID вывода | Формулировка (k из n, на уровне подтверждённого) | Область (сегмент / группа / сквозной) | Независимые респонденты | Тип доказательств | Из них П | Противоположные случаи | Статус | Уверенность | Решение (D1–D6) | Ссылки на наблюдения (ID) |
|---|---|---|---|---|---|---|---|---|---|---|
| F-01 | | | R_, R_, R_ | Ф/Н | | | Инсайт / Анекдот / Расщепление / Нет данных | высокая / средняя / низкая | | |

**Статусы** (из раздела 8 гайда):
- **Анекдот** — 1–2 независимых (Ф/Н): не использовать для решений, перенести вопрос в раздел 8.2 этого файла.
- **Инсайт, средняя уверенность** — ≥3 независимых (Ф/Н) в области гипотезы, нет ≥2 противоположных случаев.
- **Инсайт, высокая уверенность** — то же, плюс ≥2 респондента сказали это сами (П), ≥2 канала подбора; для сквозных выводов ≥2 сегмента.
- **Расщепление** — ≥2 независимых случая с каждой стороны: описать обе стороны и искать разделяющий фактор.
- **Нет данных** — тему не спрашивали или ответов нет.

## 10. Формат заметок для отправки и чеклист ПДн

### 10.1 Как присылать заметки
Свободный текст по этому порядку, один респондент в сообщении:

```
R3 · заёмщик · месяц и год · язык · версия гайда
Паспорт: (поля из раздела 2.2)
Блок 2:
- «цитата дословно, язык оригинала» — перевод — [сказал сам / в ответ на вопрос] — комментарий в скобках (мой, не респондента)
- действие или факт без цитаты: «Назвал сумму оценки и цену сделки, оценка была ниже на ~X млн сум»
Блок 3: …
Модуль A: …
GOV: …
Неожиданное: …
```

### 10.2 Чеклист ПДн (перед сохранением и отправкой)
- [ ] Нет имён, фамилий, отчеств, Telegram-ников, телефонов, e-mail.
- [ ] Нет названий банков, агентств, оценочных компаний и других организаций (только тип: «государственный банк», «частная оценочная компания»).
- [ ] Нет адресов, номеров домов и квартир, кадастровых номеров, номеров документов.
- [ ] Точные даты заменены на месяц и год; сумма сделки допускается.
- [ ] Редкие сочетания (должность + организация + необычная история) обобщены так, чтобы человека нельзя было узнать.
- [ ] Цитаты очищены: `[имя]`, `[банк]`, `[агентство]`.
- [ ] Код R выдан по порядку проведения, а не по знакомству или алфавиту.
- [ ] Записи разговора нет в репозитории, Drive, ClickUp и сообщениях (запись допустима только после согласования с Равшаном [проверить]).
- [ ] Соответствия «код — человек» нигде нет.
